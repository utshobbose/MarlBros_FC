## 2. Data Model (PostgreSQL / TypeScript)

```typescript
export type JerseySize = 'S' | 'M' | 'L' | 'XL' | 'XXL';
export type OrderStatus = 'pending_payment' | 'paid' | 'fulfilled' | 'cancelled';

export interface Order {
  id: string;
  created_at: string;
  order_reference: string;          // e.g. "MBFC-2026-1042"
  member_name: string;              // e.g. "Tanvir Ahmed"
  phone_number: string;             // e.g. "01711223344"
  jersey_size: JerseySize;          // "S" | "M" | "L" | "XL" | "XXL"
  jersey_name: string;              // Max 12 characters (e.g. "TANVIR")
  jersey_number: number;            // 0 to 99
  quantity: number;                 // 1 to 15 (default: 1)
  status: OrderStatus;              // "pending_payment" | "paid" | "fulfilled"
  notes?: string;                   // Optional fitting or delivery remarks
  total_amount: number;             // quantity * jerseyPrice (in BDT)
}
```

## 3. Resilient Storage Architecture

The application implements a dual-layer data pattern in `src/lib/supabase.ts`:
1. **Live PostgreSQL Layer (Supabase):** When `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` are provided, orders are inserted and retrieved directly through the Supabase client using PostgreSQL tables and Row-Level Security.
2. **Local Storage / Memory Fallback:** If Supabase keys are not set or if there is a temporary network interruption, operations seamlessly fall back to browser `localStorage` and seed test orders, ensuring 100% testability and zero crashes out-of-the-box.
